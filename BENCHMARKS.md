# Benchmarks

All numbers measured in the deterministic context-health simulator. Score scale: **0** = do nothing, **50** = hand-written threshold heuristic, **100** = clairvoyant planner that sees the hidden state and the future. Estimated ceiling for any observation-only policy: **~83**.

## Headline result

| Policy | Eval (200 scenarios) | Hidden confirmation (200 scenarios) |
|---|---|---|
| NOOP baseline | 0.0 | — |
| Threshold heuristic | 50.0 | — |
| Rule-teacher distill | 76.4 | 75.7 |
| Claude-teacher distill | 73.8 | 73.8 |
| **Kareem (exp_010, 3-member MLP ensemble)** | **81.5** | **81.4** |

The confirmation set was never used for selection — eval-to-confirmation gap is 0.1 points, i.e. no measurable selection drift.

## What it took to get here

100 experiments over 10 iterations, selected by an agent pipeline under a fixed compute budget. Key waypoints (all auditable under `experiments/`):

| Iteration | Best eval | What moved the score |
|---|---|---|
| 3 | 71.9 | Claude-teacher distill beats rule-teacher distill |
| 6 | 77.0 | Ensembling + standardisation |
| 8 | 80.6 | Self-play episodes added to behaviour data |
| 10 | **81.5** | `early_stop=val_regret`, `self_episodes=84`, NOOP-margin calibration |

## Honest limits

- **Sim-to-real gap is unmeasured.** The simulator's dynamics are a model, not telemetry from real agents. Shadow-mode logs (`kareem-shadow report`) are the first real-world data source.
- **Distribution:** 128k context, 40-step sessions, 6 fixed actions. Outside that envelope, retrain rather than extrapolate.
- **Confidence is diffuse** (soft-target distillation): typical max-prob 0.3–0.4. Gate on shadow-log threshold sweeps, not intuition.

## Real-session evaluation

Run with the harness in [`eval/`](eval/); raw data stays local (`eval/out/`, gitignored) because it is derived from real transcripts.

**Replay + Opus judge.** 39 real Claude Code sessions (500 KB or larger, about 7.3k tool steps, 1M-token window) were replayed through Kareem in shadow mode. An Opus judge (`claude-opus-5-5`, causal: task prompt, recent window, and the same telemetry Kareem sees) labelled 286 sampled checkpoints with one of the six actions.

| | |
|---|---|
| Kareem actions | `NOOP` 99.5%; `REINJECT_INSTRUCTIONS` 0.5%; never `COMPACT`, `PRUNE_TOOLS`, `CHECKPOINT_RESET`, `RETRIEVE_MEMORY` |
| Judge actions | `NOOP` 79%, `PRUNE_TOOLS` 13%, `COMPACT` 7%, `RETRIEVE_MEMORY` 1% |
| Agreement by context use | under 20%: 96%; 20-40%: 85%; 40-60%: 34%; above 60%: 0% |
| Rescaling inputs to the trained 128k / 40-step range | no change (agreement 77.6% vs 77.7%) |
| Feature check (leave-one-session-out, "intervene" label) | utilization alone AUC 0.93 / F1 0.78; Kareem's features AUC 0.91 / F1 0.75; plus candidate new features AUC 0.94 / F1 0.78 |

**Online A/B.** 36 valid runs (6 synthetic tasks x 2 repeats x 3 arms), Claude Sonnet via the Agent SDK, 12-turn tasks with bulky tool output, effective cap 100k tokens. Same actuator in all arms; only the decision differs.

| Arm | Score | Cost / run | Peak context | Interventions / run |
|---|---|---|---|---|
| Native (no action) | 20/20 | $1.56 | 183k | 0 |
| Threshold (compact at 70%) | 20/20 | $1.28 | 71k | 3 compactions |
| Kareem | 20/20 | $1.42 | 166k | 5 (1 compaction, 4 `PRUNE_TOOLS` notes) |

**Limits.** Tasks are synthetic and near-identical; compaction never lost information, so recall was not stressed; only cost was measured (real window is 1M, so no overflow or long-context degradation); `PRUNE_TOOLS` is signal-only in the SDK; Opus labels are not validated against real outcomes. 10 runs that died at launch (zero cost, caused by a usage limit) and 5 task groups truncated by the same limit were discarded and rerun; the runner now rejects such runs.

**Takeaway.** Kareem's inputs are sufficient (a utilization threshold predicts the judge's label), but its decision boundary comes from a simulator reward that waits until near overflow. Next: retrain on real-session labels and make `PRUNE_TOOLS` actionable.

01 · SYSTEM CONTEXT

THE GOLDEN RULE — “The harness is deterministic; the work is creative.” Python owns the loop, every stop decision, every model choice and every file write. LLMs are pure functions from a whitelisted prompt to JSON.
A cognitive software factory that searches for the best context-health intervention MLP. Four isolated LLM agents (Meta, Worker, Judge, Doc) propose, build, score and document experiments; a deterministic Python harness (run_factory.py) controls the loop; a pure-Python simulator trains and evaluates every candidate. Work proceeds in synchronous parallel waves: threads only compute — every shared-state mutation happens on the main thread, at a barrier, in iteration order.
4 LLM agents + 1 deterministic simulator 3 models · 4 ladder levels · 6 routing rules 50 turns · 60 s sim budget · judge anchored ±3 3 attempts → poison · stagnation window 10 waves of 2 (parallel ≤ 8) · refills ≤ 2/wave LLM call timeout 900 s · backoff 30·60·120·240·480 s

02 · WAVE EXECUTION PIPELINE

One wave = K iterations (default K=2, ≤8). Threads only compute; all shared-state mutations happen on the main thread at barriers, in iteration order — the outcome never depends on which thread finishes first. A snapshot of state_space.json + factory_state.json is taken before every wave; an interrupted wave is archived to experiments/_aborted/ and restored on resume.
SERIAL — main thread PARALLEL — one thread per iteration, compute-only BARRIER — join in iteration order retry loop per member: ≤3 attempts → poison
Memoisation: each member caches stage results (memo); a retry redoes only failed stages — except simulator/worker-code failures, which redo Worker + Fingerprint with the error fed back as retry_error. Poisoned members skip D’s LLM calls and still get a deterministic paper section, so the research record is complete.

03 · AGENTS & ISOLATION

Agents are pure functions from a whitelisted prompt to JSON. They have no tools; the only data they ever see is what Python assembles into the prompt. Every call runs the same AgentRunner pipeline: render template → isolation check → routed LLM call → JSON extraction → schema validation → semantic validator, with one in-place retry (rejection feedback appended, effort forced high — rule R2).
A · META-AGENT — “The Explorer”sonnet-5 · std → opus-5.5/high on streak
Reads — state_space.json · best_config.json · last_judge.json (all sanitised; analytics are Python-computed aggregates)
Writes — state-space mutations + K coordinates + hypotheses, applied by Python via StateSpace.apply_wave_proposal
Gates — JSON schema → grammar: ops add_dimension · add_values · prune_values · prune_dimension; ≤6 mutations/iter; ≤32 active dims; categorical ≤16 values; description 10–800 chars; ledger/wave hash uniqueness
Blind spot — never sees past experiment logs; 2 consecutive invalid proposals ⇒ escalated to L3 (R4)
B · WORKER — “The Builder”sonnet-5 · std (L2 if last score < 60)
Reads — next_coordinate.json · dimension definitions · full ai_docs/* corpus · retry_error after a failed attempt
Writes — model.py (PyTorch) + config.json for exactly its coordinate
Gates — schema → code_guard static AST scan before any execution → fingerprint-stage validity gates; simulator crashes return as retry_error feedback
Blind spot — never sees past experiment logs or other wave members’ code
D · JUDGE — “The Evaluator”sonnet-5 · std (L2 if last score < 60)
Reads — simulation.log · config.json with the hypothesis withheld so it cannot bias the score
Writes — judge.json: score (int 0–100) · feedback · next_steps · strengths · weaknesses
Gates — schema → anchor: |score − sim_score| ≤ 3 else JudgeAnchorError (micro-fail → escalate); the rubric can only move the deterministic sim_score within tolerance
Blind spot — never sees past experiment logs; score must stay near the deterministic metric
E · DOC — “The Researcher”sonnet-5 draft · fable-5.1 format only
Reads — config.json · judge.json · sim summary · paper snapshot (identical for the whole wave); final synthesis: paper + factory summary
Writes — iteration section (“### Iteration NNN: <title>”) + refreshed abstract + results narrative
Gates — heading pattern + no h1/h2 → format pass must be content-preserving (format_preserves) else the draft is kept → total doc failure ⇒ harness writes a deterministic fallback section
Only fable consumer — fable-5.1 exists solely for its markdown formatting pass (R5)
C · SIMULATOR — “The Ground Truth”no LLM — RoutingViolationError if any model is routed to it
What — deterministic Python subprocess: trains the Worker’s model.py, runs 50 mock context scenarios, writes canary-stamped log + metrics. Budget — 60 s hard kill; identical env for every experiment (PYTHONHASHSEED=0, CUDA off, OMP threads pinned). Role — produces sim_score, the number the Judge is anchored to and the Meta reasons over.

ISOLATION GUARD — scanned on every prompt, right before the LLM call

Why it matters: the Meta must reason over the space, not over other experiments’ logs; the Judge must score this run, not a remembered one. Isolation is what makes scores comparable across iterations — and a breach is catastrophic, so it aborts rather than degrades.

Context Health Factory · Technical Blueprint 04 / 07

04 · MODEL & EFFORT ROUTER

The LLM never picks a model. Python assigns one from failure history, using a 4-level escalation ladder and six hardcoded rules. The router is stateless — route() is a pure function of a RouteContext; all mutable escalation state lives in one EscalationTracker per iteration, so parallel iterations can never change each other’s routing. Every decision is logged to router_log.json and independently re-audited.

THE ESCALATION LADDER

R6: each iteration-level failure bumps the failing agent one level (cap L3) — tracked per iteration by EscalationTracker.

route() DECISION PIPELINE — rules applied in order

ROUTER_VERIFIED ROUTER_MISMATCH FABLE_LEAK verdict computed per experiment at wave close

Context Health Factory · Technical Blueprint 05 / 07

05 · FAILURE SEMANTICS & STOP CONDITIONS

Three failure severities, three different fates. Micro-fails are absorbed by the iteration retry loop (escalate, retry ≤3, then poison the coordinate). Macro-fails abort the factory instantly. InfraUnavailable pauses with fully resumable state. An unexpected exception inside a stage is converted to HarnessStageError (a micro-fail) — the factory survives its own bugs.

EXCEPTION HIERARCHY

ITERATION RETRY STATE MACHINE — per member, per attempt

META-DONE CONDITIONS — checked by Python before any agent runs

A halt is not the end of the pipeline: hidden confirmation and the final synthesis run after it — see page 06. If the factory is rerun after halting, it exits immediately (state["halted"]); --fresh archives the previous run and reseeds.

06 · SIMULATOR & EVALUATION INTEGRITY

The simulator is the factory’s ground truth: a pure-Python subprocess that trains the Worker’s model on synthetic context-health scenarios and scores it. Scores stay honest through four mechanisms: canary-stamped output, a functional fingerprint that detects duplicate models, a Judge anchored ±3 to the deterministic sim_score, and a hidden confirmation set that breaks the evaluation set’s winner’s curse.

SIMULATION PROTOCOL — parent spawns, child computes, parent validates

FINGERPRINT → DEDUPE → REFILL

JUDGE ANCHOR — rubric within tolerance of ground truth

CALIBRATION BASELINES — measured at preflight

noopheuristicoracleteacher_v2clairvoyant mean return per policy → state["baselines"]

SELECTION vs CONFIRMATION — beating the winner’s curse

  • Selection (spec rule): best_model.py = highest judge score; ties broken by sim_score. Synced at phase C of every wave.
  • Confirmation (harness, at halt): re-score candidates on 200 hidden scenarios (seeds 95000+) never used for selection.
  • Candidates: every iteration sim-tied within 2 × the typical paired SE of the best (cap CONFIRM_TOP_K = 6; functional duplicates excluded).
  • Statistics: paired per-turn return differences vs the selected best; mean Δ and its SE reported per candidate.
  • Outputs: confirmation.json · best_model_confirmed.py · CONFIRMATION block in the paper · factory summary names selected vs confirmed best.
  • Also at halt: final synthesis (doc/final over paper + summary) → factory_report.json (verify_run macro/micro audit) → ai_docs re-checksumed.

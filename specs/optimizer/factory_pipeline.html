01 · THE RUN, END TO END

THE GOLDEN RULE — “The harness is deterministic; the work is creative.” Python owns the loop, every stop decision, every model choice and every file write. Agents are pure functions from a whitelisted prompt to JSON.
What actually happens when you type python factory/run_factory.py. Every box below is Python code in run_factory.py; LLM agents exist only inside run_wave() (page 02). There is exactly one clean way out — halt(reason) — and three ways to stop early.

02 · ONE WAVE AS A SEQUENCE DIAGRAM

A wave builds K = --parallel iterations at once. Time flows down; bars on lifelines mark busy threads; gray/blue/teal/purple bands are serial — main thread only, orange/green bands are parallel — member threads. Threads only compute: every shared-state write happens on the main thread at a barrier, in iteration order, so the outcome never depends on which thread finishes first.
A Meta: 1 call, ≤3 attempts B1 build ×K · B2 dedupe · B3 simulate+judge ×K C ledger update · D document ×K · E paper + close refills ≤ 2/wave · sim timeout 60 s · judge anchored ±3
—— call / file write · ⇢ dashed = return · white bar on a lifeline = thread busy · bands: blue/gray/teal/purple = serial (main thread) · orange/green = parallel (member threads)

03 · THE THREE NESTED STATE MACHINES

The factory is three state machines stacked. A failure at a lower level is caught, retried and escalated there; it only travels upward when local retries exhaust. Iteration failures feed the wave machine; two identically-poisoned waves trip the circuit breaker and pause the run.

04 · THE FEEDBACK LOOP BETWEEN WAVES

Nothing resets between waves except the member threads. Wave N's outputs are written to disk in phases C/E and read back as wave N+1's inputs — the Meta prompt, the router context, the dedupe set and the halt test. This is the whole learning loop: there is no other memory.
